# سامانه مدیریت انبار (StoreRoom)

نرم‌افزار تحت وب مدیریت موجودی، ورود و خروج کالا، مشتریان، تأمین‌کنندگان و کاربران.
رابط کاربری کاملاً فارسی و راست‌به‌چپ، بدون وابستگی به اینترنت در زمان اجرا.

---

## امکانات

| بخش | توضیح |
|---|---|
| داشبورد | آمار لحظه‌ای موجودی، ارزش انبار، رسید و حواله‌های در انتظار تأیید، کالاهای رو به اتمام |
| کالاها | ثبت کالا با بارکد، واحد شمارش، حداقل/حداکثر موجودی، گروه‌بندی درختی |
| رسید ورودی | ثبت رسید خرید با شماره فاکتور، مالیات، شماره بچ، تاریخ انقضا و محل قفسه |
| حواله خروجی | ثبت خروج با ۷ نوع (فروش، مصرف داخلی، کمک، ضایعات، مرجوعی، انتقال، پرت) |
| گردش کالا | تفکیک رسید ورودی و خروجی، با تاریخچه کامل |
| انبارها | چند انبار با موجودی مستقل برای هرکدام |
| مشتریان و تأمین‌کنندگان | اطلاعات تماس، آدرس و کد اقتصادی |
| کاربران و نقش‌ها | سه نقش با تفکیک دسترسی |
| گزارش‌ها | ارزش موجودی، پرتره کالا، گردش در بازه دلخواه |
| چاپ | چاپ رسید و حواله با قالب اختصاصی |

## پیش‌نیازها

| مورد | نسخه |
|---|---|
| .NET SDK | ۱۰.۰ یا بالاتر (`net10.0`) |
| SQL Server | 2019 یا بالاتر (نسخه Express هم کافی است) |
| سیستم‌عامل | Windows / Linux / macOS |

> اتصال پیش‌فرض از احراز هویت ویندوز (`Trusted_Connection`) استفاده می‌کند.
> برای سرور لینوکسی یا اگر کاربر ویندوزیِ دیتابیس متفاوت است،
> رشته اتصال را در `Web/appsettings.json` تغییر دهید.

## راه‌اندازی

```bash
git clone <آدرس مخزن>
cd StoreRoom

# بازیابی بسته‌ها
dotnet restore

# اجرا
dotnet run --project Web/Web.csproj
```

سپس در مرورگر باز کنید: **http://localhost:5219**

دیتابیس در اولین اجرا **خودکار** ساخته می‌شود؛ نیازی به اسکریپت جداگانه نیست.
مهاجرت‌های EF Core اجرا و جدول‌ها، نقش‌ها و کاربر مدیر ایجاد می‌شوند.

### تغییر درگاه

```bash
dotnet run --project Web/Web.csproj --urls "http://localhost:8080"
```

### اجرای حالت عملیاتی

حالت `Development` داده نمایشی می‌سازد. برای نصب واقعی:

```bash
export ASPNETCORE_ENVIRONMENT=Production
dotnet run --project Web/Web.csproj
```

در محیط عملیاتی، نقش‌ها ساخته می‌شوند و کاربر `admin` فقط در صورتی ایجاد می‌شود که
رمزش از پیکربندی تعریف شده باشد. اگر نباشد، برنامه با خطا متوقف می‌شود: ساخت
خودکار مدیر با رمز پیش‌فرضِ شناخته‌شده، عملاً دسترسی کامل به سیستم را عمومی
می‌کند. به همین دلیل رمز داخل کد نگهداری نمی‌شود:

```bash
dotnet user-secrets --project Web/Web.csproj set "Seed:AdminPassword" "<رمز-قوی>"
```

در محیط عملیاتی، ساخت **کاربران نمایشی** و **داده‌های نمایشی** غیرفعال است تا سیستم
با حساب‌هایی با رمز ثابت و قابل حدس بالا نیاید.


---

## حساب‌های پیش‌فرض

| نام کاربری | رمز | نقش | توضیح |
|---|---|---|---|
| `admin` | از `Seed:AdminPassword` | Admin | در توسعه: پیش‌فرض `Admin@123` · در عملیاتی: اجباری |
| `manager` | `Manager@123` | Manager | فقط در حالت Development |
| `user` | `User@123` | User | فقط در حالت Development |

> **توجه:** در توسعه، به‌جز حساب `admin` دو حساب `manager` و `user` با رمزهای ثابت
> و داده‌های نمایشی ساخته می‌شوند تا بتوان جریان ثبت و تأیید را امتحان کرد. این
> حساب‌ها فقط برای نمایش هستند و هیچ داده واقعی پشت آن‌ها نیست.

## ساختار پروژه

```
StoreRoom/
├── Domain/              موجودیت‌های دامنه (Product, GoodsReceipt, GoodsIssue, ...)
├── Application/         رابط سرویس‌ها و پیاده‌سازی منطق کسب‌وکار
│   ├── Constants/       پیام‌های خطا
│   ├── Dto/             اشیای انتقال داده
│   └── Features/
│       ├── Definition/  قرارداد سرویس‌ها (interface)
│       └── Implementation/  پیاده‌سازی سرویس‌ها
├── Persistence/         EF Core: DbContext، مهاجرت‌ها، داده اولیه
│   ├── Context/
│   ├── Migrations/
│   └── SeedData/
├── Web/                 لایه MVC: کنترلر، ویو، مدل، اعتبارسنجی
│   └── Infrastructure/  ابزارهای داخلی وب (اعتبارسنجی، تبدیل رقم، ...)
└── Tests/StoreRoom.Tests/  تست‌های واحد
```

وابستگی‌ها یک‌طرفه است: `Web → Application → Domain` و `Web → Persistence`.
پروژه `Persistence` به `Application` و `Domain` ارجاع دارد و برعکس نیست.

## نکات فنی

### منطق موجودی

موجودی در دو ستون نگهداری می‌شود: `Product.Number` (موجودی هر کالا) و
`Warehouse.Number` (مجموع اقلام یک انبار). هنگام **تأیید** هر سند، این دو با
`ExecuteUpdateAsync` به‌روزرسانی می‌شوند:

- رسید تأییدشده → `Number += Quantity`
- حواله تأییدشده → `Number -= Quantity`

برای جلوگیری از موجودی منفی در حالت همزمانی، به‌روزرسانی شرطی و درون
تراکنش انجام می‌شود (`WHERE Number >= Quantity`)، به‌طوری‌که اگر سطر به‌روز نشد
عملیات rollback می‌شود. شرط در خودِ دستور `UPDATE` است، نه یک `SELECT` قبل از
آن؛ بنابراین دو کاربر همزمان نمی‌توانند هر دو از یک موجودی استفاده کنند.

> سند در وضعیت «در انتظار تأیید» هیچ اثری روی موجودی ندارد. این رفتار عمدی است:
> ثبت اولیه توسط کاربر انبار انجام می‌شود و تأیید نهایی در اختیار سرپرست.

### اعتبارسنجی

منطق اعتبارسنجی در `Web/Infrastructure/Validators.cs` و مستقل از دیتابیس است،
بنابراین مستقیماً تست شده است:

- `ReceiptValidator` — رسید ورودی
- `IssueValidator` — حواله خروجی (شامل قاعده «موجودی نباید منفی شود»)

### تبدیل ارقام

`PersianNumberConverter` ورودی کاربر را نرمال می‌کند:

- ارقام فارسی `۰-۹` و عربی `٠-٩` → لاتین (برای ذخیره در دیتابیس)
- جداکننده هزارگان `٬` و اعشار `٫` فارسی → قالب استاندارد
- حذف نویسه‌های اضافی از ورودی عددی

## تنظیمات

`Web/appsettings.json`:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=.;Database=StoreroomWebDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=True"
  }
}
```

برای رمز عبور SQL Server به‌جای احراز هویت ویندوز:

```json
"DefaultConnection": "Server=.;Database=StoreroomWebDb;User Id=sa;Password=***;TrustServerCertificate=True;MultipleActiveResultSets=True"
```

برای دیتابیس جداگانه در هر محیط، از **User Secrets** استفاده کنید
(به‌جای قرار دادن رمز در فایل):

```bash
cd Web
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Server=...;Password=..."
```

## استقرار

### انتشار

```bash
dotnet publish Web/Web.csproj -c Release -o ./publish
```

خروجی در `publish/` قرار می‌گیرد و روی هر ماشینی با .NET Runtime ۱۰ اجرا می‌شود.

### به‌عنوان سرویس ویندوز

```bash
dotnet publish Web/Web.csproj -c Release -o C:\Sites\StoreRoom
sc.exe create StoreRoom binPath= "C:\Sites\StoreRoom\Web.exe" start= auto
sc.exe start StoreRoom
```

### نکات امنیتی برای استقرار

- `ASPNETCORE_ENVIRONMENT=Production` تنظیم کنید تا داده نمایشی ساخته نشود
- رمز پیش‌فرض `admin` را تغییر دهید
- برنامه را پشت IIS یا Nginx قرار دهید و TLS را روی آن فعال کنید
- از دیتابیس نسخه پشتیبان منظم بگیرید

## پشتیبان‌گیری

تمام اطلاعات در یک دیتابیس SQL Server به نام `StoreroomWebDb` است.
کافی است از آن پشتیبان بگیرید:

```sql
BACKUP DATABASE [StoreroomWebDb]
TO DISK = N'D:\Backups\StoreroomWebDb.bak'
WITH FORMAT, COMPRESSION;
```

بازیابی:

```sql
RESTORE DATABASE [StoreroomWebDb]
FROM DISK = N'D:\Backups\StoreroomWebDb.bak'
WITH REPLACE;
```
